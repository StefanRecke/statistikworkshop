3.1 Fehlende Werte ersetzen?

Ein kurzes Beispiel am BMI (1709 fehlende Werte). Fehlende Werte zu löschen (Complete Case) ist mit die häufigste Vorgehensweise. Sie kostet aber Teilnehmer. Eine mögliche “Reparatur” könnte eine Imputation sein (hier: Mean Imputation).

R-Code anzeigen 
bmi_beob <- nh$bmi[!is.na(nh$bmi)]                          # nur beobachtete Werte
bmi_imp  <- replace(nh$bmi, is.na(nh$bmi), mean(bmi_beob))  # fehlende = Mittelwert

tibble(
  Methode    = c("Complete Case (löschen)", "Mean Imputation (Mittelwert)"),
  n          = c(length(bmi_beob), length(bmi_imp)),
  Mittelwert = c(mean(bmi_beob), mean(bmi_imp)),
  SD         = c(sd(bmi_beob), sd(bmi_imp))
) |>
  mutate(across(where(is.numeric), \(x) round(x, 2))) |>
  knitr::kable(caption = "Zwei Umgangsweisen mit den BMI-Lücken – der Mittelwert bleibt fast gleich, die Streuung (SD) aber schrumpft.")
Zwei Umgangsweisen mit den BMI-Lücken – der Mittelwert bleibt fast gleich, die Streuung (SD) aber schrumpft.
Methode n Mittelwert SD
Complete Case (löschen) 14879 28.54 6.14
Mean Imputation (Mittelwert) 16588 28.54 5.82

Aber Achtung, bei der Mean Imputation sinkt die Streuung künstlich, denn alle ergänzten Werte sitzen exakt auf dem Mittelwert. Eine zu kleine Streuung erzeugt später zu enge Konfidenzintervalle („Scheingenauigkeit”) vor. Sauberer lösen lässt sich das mit Verfahren, die diese Unsicherheit mitführen (Stichwort Multiple Imputation).

4.3 Zusammenhangsmaße: RD, RR und OR mit 95%-KI

Frage: Wie groß ist der Zusammenhang – als Risikodifferenz, relatives Risiko und Odds Ratio, jeweils mit Konfidenzintervall?

HinweisAlltagssprache
  • Risikodifferenz (RD): Um wie viele Prozentpunkte unterscheiden sich zwei Gruppen? („5 von 100 mehr“)
  • Relatives Risiko (RR): Wie viel mal wahrscheinlicher ist die Erkrankung? („doppelt so oft“)
  • Odds Ratio (OR): Verhältnis der Chancen – bei seltenen Ereignissen ≈ RR, sonst größer.
R-Code anzeigen 
# Exposition = Parodontitis (Ja), Outcome = Diabetes (Ja).
# epitools erwartet die Referenz zuerst: unexponiert (Nein) in Zeile 1,
# kein Ereignis (Nein) in Spalte 1 – dann steht der Effekt in Zeile 2.

6.3 Confounding am Beispiel Rauchen

Die Regression schätzt den Effekt eines Merkmals, während andere konstant gehalten werden. Damit lässt sich prüfen, ob ein beobachteter Zusammenhang in Wahrheit über eine Störgröße läuft. Bei einem Ja/Nein-Outcome (Parodontitis vorhanden?) ist die logistische Regression das passende Werkzeug.

Frage: Verändert sich der BMI-Effekt auf Parodontitis, wenn wir für Rauchen adjustieren?

7.5 Lohnt sich eine zusätzliche Variable? Modellvergleich

Frage: Wird das Modell besser, wenn Diabetes dazukommt – oder reichen Alter, Geschlecht und Rauchen?

7.6 Zwei Fragen muss man sich stellen

  1. Passt das größere Modell besser zu den Daten? → Likelihood-Ratio-Test (LRT), ergänzt um AIC/BIC. Das ist eine Frage an den Modellfit.
  2. Sagt es auch besser vorher? → ΔAUC, Kalibrierung, Net Benefit.

Der LRT beantwortet nur Frage 1.

Voraussetzung: Die Modelle müssen genestet sein (Modell 0 = Modell 1 minus diab) und auf exakt denselben Zeilen geschätzt werden.

AUC und Kalibrierung sagen nichts darüber, ob ein Modell zu besseren Entscheidungen führt. 7.8 Regression vs. Machine Learning

Hätte ein flexibles Machine-Learning-Modell (z. B. Random Forest, Boosting) unser logistisches Modell geschlagen? In Workshops und Papern wird gern reflexartig zu Machine Learning gegriffen. Ich möchte an dieser Stelle bewusst auf ein eigenes ML-Modell verzichten.

Ein systematischer Vergleich (Christodoulou u. a. 2019) fand bei klinischen Prädiktionsproblemen mit tabellarischen Daten keinen Vorteil von Machine Learning gegenüber der logistischen Regression in der Diskrimination (AUC). Dafür ist ML dort oft:

  • schlechter kalibriert – RF/Boosting liefern häufig zu extreme Wahrscheinlichkeiten;
  • schwerer zu interpretieren;
  • anfälliger für Overfitting bei kleinem EPV.

Mehr Flexibilität ≠ besseres Modell.

Ein kurzes Beispiel am **BMI** (`r sum(is.na(nh$bmi))` fehlende Werte). Fehlende Werte zu löschen (Complete Case) ist mit die häufigste Vorgehensweise. Sie kostet aber Teilnehmer. Eine mögliche "Reparatur" könnte eine Imputation sein (hier: Mean Imputation).

## Zusammenhangsmaße: RD, RR und OR mit 95%-KI {#sec-A3}

**Frage:** Wie groß ist der Zusammenhang – als **Risikodifferenz**, **relatives Risiko** und **Odds Ratio**, jeweils mit Konfidenzintervall?

::: callout-note
## Alltagssprache

-   **Risikodifferenz (RD):** Um wie viele Prozentpunkte unterscheiden sich zwei Gruppen? („5 von 100 mehr“)
-   **Relatives Risiko (RR):** Wie viel *mal* wahrscheinlicher ist die Erkrankung? („doppelt so oft“)
-   **Odds Ratio (OR):** Verhältnis der *Chancen* – bei seltenen Ereignissen ≈ RR, sonst größer.
:::

```{r}
#| label: A3-effektmasse
# Exposition = Parodontitis (Ja), Outcome = Diabetes (Ja).
# epitools erwartet die Referenz zuerst: unexponiert (Nein) in Zeile 1,
# kein Ereignis (Nein) in Spalte 1 – dann steht der Effekt in Zeile 2.
dat_a3 <- nh |> filter(!is.na(diab), !is.na(perio2))

tab_epi <- table(
  Parodontitis = factor(dat_a3$perio2, levels = c("Nein", "Ja")),
  Diabetes     = factor(dat_a3$diab,   levels = c("Nein", "Ja"))
)
tab_epi

rr_out <- riskratio.wald(tab_epi)   # RR für exponiert (Zeile 2)
or_out <- oddsratio.wald(tab_epi)   # OR für exponiert (Zeile 2)

a3_ergebnis <- tibble(
  Maß = c("Relatives Risiko (RR)", "Odds Ratio (OR)"),
  Schätzer = c(rr_out$measure[2, 1], or_out$measure[2, 1]),
  KI_unten = c(rr_out$measure[2, 2], or_out$measure[2, 2]),
  KI_oben  = c(rr_out$measure[2, 3], or_out$measure[2, 3])
) |> mutate(across(where(is.numeric), \(x) round(x, 2)))

# Risikodifferenz separat (base R, immer verfügbar)
a <- tab_epi["Ja","Ja"];   b <- tab_epi["Ja","Nein"]
c <- tab_epi["Nein","Ja"]; d <- tab_epi["Nein","Nein"]

                 Schätzer = round(p1 - p0, 3),
                 KI_unten = round(p1 - p0 - 1.96*se_rd, 3),
                 KI_oben  = round(p1 - p0 + 1.96*se_rd, 3))
```

## Ein-Stichproben-t-Test: BMI vs. WHO-Normalwert 21,7 {#sec-A6}

**Frage:** Weicht der mittlere BMI der Stichprobe vom WHO-Referenzwert 21.7 kg/m² ab?

```{r}

t_bmi
```

Der mittlere BMI beträgt **`r round(t_bmi$estimate, 1)` kg/m²** (95%-KI `r round(t_bmi$conf.int[1], 1)`–`r round(t_bmi$conf.int[2], 1)`), p `r ifelse(t_bmi$p.value < 0.001, "< 0.001", round(t_bmi$p.value, 3))`. ## Hinweis

Den **p-Wert immer zusammen mit dem Konfidenzintervall**. Das KI zeigt **Richtung und Größe** des Effekts – **klinische Relevanz ≠ statistische Signifikanz**. Bei großem `n` wird auch ein winziger, unwichtiger Unterschied „signifikant“.
:::

## Confounding am Beispiel Rauchen {#sec-A10}

Die **Regression** schätzt den Effekt eines Merkmals, während andere konstant gehalten werden. Damit lässt sich prüfen, ob ein beobachteter Zusammenhang in Wahrheit über eine **Störgröße** läuft. Bei einem Ja/Nein-Outcome (Parodontitis vorhanden?) ist die **logistische Regression** das passende Werkzeug.

**Frage:** Verändert sich der BMI-Effekt auf Parodontitis, wenn wir für Rauchen adjustieren?

```{r}
#| label: A10-confounding
dat_a10 <- nh |> filter(!is.na(b_perio), !is.na(bmi), !is.na(smk))

m_roh <- glm(b_perio ~ bmi, data = dat_a10, family = binomial)        # unadjustiert
m_adj <- glm(b_perio ~ bmi + smk, data = dat_a10, family = binomial)  # für Rauchen adjustiert

conf_tab <- tibble(
  Modell = c("roh (nur BMI)", "adjustiert (+ Rauchen)"),
  OR_bmi = round(c(exp(coef(m_roh)["bmi"]), exp(coef(m_adj)["bmi"])), 3)
)
conf_tab |>
  mutate(Änderung_Prozent = round(100 * (OR_bmi - first(OR_bmi)) / first(OR_bmi), 1)) |>
  knitr::kable(caption = "Ändert sich das OR für BMI nach Adjustierung deutlich (> ~10 %), spricht das für Confounding durch Rauchen.")
```

::: callout-note
## Confounding vs. Effektmodifikation

-   **Confounding**: Eine Störgröße (Rauchen) verzerrt den *einen* wahren Effekt. Lösung: **adjustieren** – der Effekt wird auf *einen* korrigierten Wert gebracht.
-   **Effektmodifikation**: Der Effekt ist in Untergruppen *wirklich verschieden* – der BMI wirkt z. B. bei Jüngeren anders als bei Älteren.
:::

# Prädiktionsmodell für Parodontitis {#sec-teilB}

::: callout-tip
## Überblick

Ein gutes Vorhersagemodell braucht **drei** Dinge: **Diskrimination** (Fälle von Nicht-Fällen trennen), **Kalibrierung** (Wahrscheinlichkeiten stimmen zahlenmäßig) und **klinischen Nutzen** (bessere Entscheidungen als „alle/niemand behandeln“). Unser binäres Outcome (Parodontitis vorhanden?) führt zur **logistischen Regression**. ## Analysestichprobe & Basistabelle (Table 1) {#sec-B0}

Outcome ist die binäre Parodontitis (`b_perio`: 1 = vorhanden, 0 = keine). Als Prädiktoren wählen wir vier klinisch naheliegende, gut erhebbare Merkmale: Alter (`age`), Geschlecht (`sex`), Rauchen (`smk`) und Diabetes (`diab`). Unsere Stichprobe ist eine Complete-Case Analyse.


### Kalibrierung: stimmen die Wahrscheinlichkeiten? {#sec-B3b}

**Frage:** Wenn das Modell „30 % Risiko“ sagt – erkranken dann tatsächlich \~30 %?

```{r}
#| label: B3b-kalibrierung
#| fig-cap: "Liegen die Punkte auf der Diagonale, sind die vorhergesagten Risiken korrekt (gut kalibriert)."
# Kalibrierung „im Großen“ (in-the-large) und Kalibrierungs-Slope
# Slope = Steigung, wenn man das Outcome auf den Logit der Vorhersage regressiert.
cal_slope_fit <- glm(b_perio ~ qlogis(pmin(pmax(p_glm, 1e-6), 1-1e-6)),
                     data = dat_b, family = binomial)
cal_slope <- coef(cal_slope_fit)[2]
cal_large <- mean(dat_b$p_glm) - mean(dat_b$b_perio)  # Über-/Unterschätzung im Mittel

# Kalibrierungskurve über gebinnte Beobachtungen + Loess
kal_df <- dat_b |>
  mutate(bin = ntile(p_glm, 10)) |>
  group_by(bin) |>
  summarise(pred = mean(p_glm), obs = mean(b_perio), .groups = "drop")

ggplot(dat_b, aes(x = p_glm, y = b_perio)) +
  geom_abline(slope = 1, intercept = 0, linetype = "dashed", colour = "grey") +
  geom_smooth(method = "loess", se = TRUE, colour = "steelblue") +
  geom_point(data = kal_df, aes(x = pred, y = obs), colour = "firebrick", size = 2) +
  coord_equal(xlim = c(0, max(kal_df$pred)*1.1), ylim = c(0, max(kal_df$obs)*1.1)) +
  labs(title = "Kalibrierungsplot – Modell 1",
       subtitle = paste0("Calibration-in-the-large = ", round(cal_large, 3),
                         " | Calibration Slope = ", round(cal_slope, 2)),
       x = "vorhergesagte Wahrscheinlichkeit", y = "beobachteter Anteil")
```

Ein **Slope ≈ 1** und **Calibration-in-the-large ≈ 0** bedeuten gute Kalibrierung. Ein Slope \< 1 deutet auf **zu extreme** Vorhersagen (typisch bei Overfitting): hohe Risiken zu hoch, niedrige zu niedrig geschätzt.

### Optimismus-Korrektur per Bootstrap {#sec-B3c}

**Frage:** Wie stark ist unser Modell **auf den eigenen Daten geschönt** (Optimismus/Overfitting)?

```{r}
boot_tab <- tibble(
  Kennzahl = c("AUC (apparent)", "AUC (optimismus-korrigiert)", "Calibration Slope (korrigiert)"),

)

```

Die **korrigierte AUC** (`r auc_glm_corr`) ist realistischer als die apparente. Der Abstand zeigt, wie stark das Modell auf den eigenen Daten „geschönt“ war (Overfitting).

## Lohnt sich eine zusätzliche Variable? Modellvergleich {#sec-B4}

**Frage:** Wird das Modell **besser**, wenn Diabetes dazukommt – oder reichen Alter, Geschlecht und Rauchen?

## Zwei Fragen muss man sich stellen

1.  **Passt das größere Modell besser zu den Daten?** → **Likelihood-Ratio-Test (LRT)**, ergänzt um **AIC/BIC**. Das ist eine Frage an den **Modellfit**.
2.  **Sagt es auch besser vorher?** → **ΔAUC**, **Kalibrierung**, **Net Benefit**.

Der LRT beantwortet nur Frage 1.

Voraussetzung: Die Modelle müssen genestet sein (Modell 0 = Modell 1 minus `diab`) und auf exakt denselben Zeilen geschätzt werden.


### Schritt 1: Modellfit – LRT, AIC und BIC {#sec-B4a}

```{r}
#| label: B4a-lrt
fit_glm0 <- glm(b_perio ~ age + sex + smk, data = dat_b, family = binomial)  # ohne Diabetes
fit_glm1 <- fit_glm                                                  # mit Diabetes (aus @sec-B2)

# LRT: 2 x Differenz der Log-Likelihoods, Chi²-verteilt mit df = zusätzliche Parameter
lrt <- anova(fit_glm0, fit_glm1, test = "LRT")
chi_lrt <- lrt$Deviance[2]
df_lrt  <- lrt$Df[2]
p_lrt   <- lrt$`Pr(>Chi)`[2]

tibble(
  Modell = c("Modell 0: ohne Diabetes", "Modell 1: mit Diabetes"),
  AIC = round(c(AIC(fit_glm0), AIC(fit_glm1)), 1),
  BIC = round(c(BIC(fit_glm0), BIC(fit_glm1)), 1)
) |>
  knitr::kable(caption = "Modellfit im Vergleich – bei AIC und BIC gilt: kleiner ist besser.")
```

χ² = `r round(chi_lrt, 1)` bei `r df_lrt` Freiheitsgrad(en), p = `r format.pval(p_lrt, digits = 2, eps = 0.001)`; die AIC-Differenz beträgt `r round(AIC(fit_glm0) - AIC(fit_glm1), 1)` (positiv = Modell 1 besser, Faustregel \> 2). `r if (p_lrt < 0.05) "Das größere Modell passt also **signifikant besser** zu den Daten." else "Das größere Modell passt **nicht signifikant besser**."`

## Decision Curve Analysis {#sec-B3d}

AUC und Kalibrierung sagen nichts darüber, ob ein Modell zu besseren Entscheidungen führt. Genau das prüft die Decision Curve Analysis: Sie trägt den Net Benefit über die Behandlungsschwelle auf und vergleicht das Modell mit den beiden Strategien ohne Modell – alle behandeln und niemanden behandeln. Das ist an der Stelle aber nicht mehr Teil des Manuskripts.

## Regression vs. Machine Learning

Hätte ein flexibles Machine-Learning-Modell (z. B. Random Forest, Boosting) unser logistisches Modell geschlagen? In Workshops und Papern wird gern reflexartig zu Machine Learning gegriffen. Ich möchte an dieser Stelle bewusst auf ein eigenes ML-Modell verzichten.

Ein systematischer Vergleich [@christodoulou2019] fand bei klinischen Prädiktionsproblemen mit tabellarischen Daten keinen Vorteil von Machine Learning gegenüber der logistischen Regression in der Diskrimination (AUC). Dafür ist ML dort oft:

-   **schlechter kalibriert** – RF/Boosting liefern häufig **zu extreme** Wahrscheinlichkeiten;
-   **schwerer zu interpretieren**;
-   anfälliger für Overfitting bei kleinem EPV.

**Mehr Flexibilität ≠ besseres Modell.**
